👥 آموزش کاربران و گروه‌ها

لینوکس از روز اول چندکاربره است — همه‌چیز به «چه کسی» وصل است.

هویت در لینوکس

هر کاربر یک UID عددی دارد (root همیشه 0). هر کاربر عضو یک یا چند گروه است (هر گروه هم GID دارد). ترکیب «کاربر + گروه‌ها» مشخص می‌کند چه چیزی را مجازید (ببینید درس دسترسی‌ها).

من کی‌ام؟

whoami          # نام کاربری فعلی
id              # نام + UID + همه‌ی گروه‌ها
groups          # فقط گروه‌ها

در آزمایشگاه، دسترسی root می‌گیرید و با su می‌توانید «شخص دیگری» شوید:

su lab          # سوئیچ به کاربر lab (رمزش را بدانید)
su - lab        # با محیط کامل (home و متغیرها) — خط تیره راست واقعی است
whoami          # حالا: lab

دفتر کاربران: /etc/passwd

cat /etc/passwd
# lab:x:1001:1001:Lab User,,,:/home/lab:/bin/bash
#  ↑   ↑  ↑    ↑       ↑          ↑          ↑
# نام رمز UID GID   GECOS       home       شل
ستونمعنی
نامنام کاربری
xرمز در فایل جدا (/etc/shadow) است
UIDشماره‌ی یکتا — 0 یعنی root!
GIDگروه اصلی
GECOSتوضیح آزاد (نام واقعی، تلفن، ...) — اینجا گاهی رازها پنهان می‌شوند!
homeپوشه‌ی خانه
شل/bin/false یعنی این کاربر نمی‌تواند لاگین کند

هش رمزها در /etc/shadow است که فقط root می‌خواندش — به شکل $6$Salt$Hash.... یکی‌طرفه است: از روی هش نمی‌شود رمز را «خواند»، فقط حدس‌ها را می‌شود چک کرد.

ساختن کاربر

useradd -m -s /bin/bash ali     # ساخت با -m یعنی خانه بساز
passwd ali                      # گذاشتن/تغییر رمز
usermod -aG docker ali          # اضافه به گروه (a=append حتما با G)
userdel -r ali                  # حذف با خانه (-r)
چرا aG نه فقط G؟ usermod -G x ali کاربر را از همه‌ی گروه‌های قبلی خارج و فقط در x می‌گذارد! با -aG «اضافه» می‌کنید. کلاسیک‌ترین اشتباه مدیرهای تازه‌کار.

sudo در یک خط

sudo یعنی «این یک دستور را با اختیارات دیگری اجرا کن». اجازه‌ها در /etc/sudoers و /etc/sudoers.d/ است. قاعده‌ی طلایی امنیت: کار با کمترین اختیارِ لازم — root فقط وقتی که واقعا لازم است.

تمرین (در آزمایشگاه خودتان انجام دهید)

  1. UID خودتان و گروه‌هایتان را با یک دستور نشان دهید.
  2. کاربری به نام tester با خانه بسازید، رمز بگذارید و با su واردش شوید و برگردید.
  3. ستون GECOS کاربر root در passwd چیست؟
  4. کدام کاربران سیستم شل‌شان /usr/sbin/nologin است؟ بشمارید.
  5. چرا هشِ رمز در passwd نیست و در shadow جدا شده؟

پاسخ‌ها:

پاسخ ۱

id

پاسخ ۲

useradd -m -s /bin/bash tester && passwd tester && su tester → exit

پاسخ ۳

grep '^root:' /etc/passwd | cut -d: -f5 → معمولا «root»

پاسخ ۴

grep -c nologin /etc/passwd یا grep nologin /etc/passwd | wc -l

پاسخ ۵

چون passwd باید برای همه خوانا باشد (برای id/ls و ...) اما هش‌ها فقط مال root — جداسازی = امنیت.

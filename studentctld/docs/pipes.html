⛓️ آموزش لوله‌ها و تغییر مسیر

ابزارهای کوچک، زنجیر‌شده — ایده‌ی اصلی یونیکس.

همه‌چیز جریان است

هر دستور دو جریان خروجی دارد: stdout (خروجی اصلی) و stderr (پیام‌های خطا). و یک ورودی: stdin. لینوکس به شما اجازه می‌دهد این جریان‌ها را مثل لوله‌کشی جابه‌جا کنید.

لوله: خروجی یکی، ورودی دیگری

ls /etc | wc -l                # چند فایل در /etc؟
cat server.log | grep ERROR    # فقط خط‌های خطا
history | tail -20             # ۲۰ دستور آخر
ps aux | grep cron             # دنبال فرایند cron بگرد

خروجی دستور چپ، مستقیم می‌شود ورودی دستور راست. می‌توانید زنجیر را هرقدر خواستید ادامه دهید — هر حلقه یک کار کوچک می‌کند.

تغییر مسیر: جایی غیر از صفحه‌نمایش

ls > list.txt                  # خروجی در فایل (بازنویسی!)
echo "new line" >> list.txt    # اضافه‌کردن به انتهای فایل
grep FLAG big.log > found.txt  # فقط نتیجه‌ی جستجو ذخیره شود
sort names.txt < source        # ورودی از فایل (کم‌کاربرد‌تر)
wc -l < list.txt               # فقط عدد، بدون نام فایل
> در برابر >>: تک‌فلش «بازنویسی» می‌کند (قبلی پاک می‌شود!)، دوتایی «اضافه» می‌کند. با تک‌فلش احتیاط — نمی‌شود برگرداند.

stderr: خطاها جدا حرکت می‌کنند

ls /nope 2> errors.txt         # فقط پیام خطا در فایل
ls /etc /nope > out.txt 2>&1   # خروجی و خطا هر دو در یک فایل
grep root /etc/passwd 2>/dev/null   # خطاها را دور بریز (/dev/null سیاه‌چاله است)

tee: هم ببین، هم ذخیره کن

ls -l | tee snap.txt           # روی صفحه هم نشان می‌دهد هم در فایل می‌نویسد
make 2>&1 | tee build.log      # لاگِ ساخت را زنده ببین و نگه دار

xargs: خروجی را به «آرگومان» تبدیل کن

لوله خروجی را به ورودی می‌دهد؛ اما بعضی دستورها ورودی نمی‌گیرند، آرگومان می‌خواهند. xargs این پل است:

cat files.txt | xargs rm       # هر خط = یک آرگومان برای rm
find . -name '*.tmp' | xargs rm       # پاک کردن همه‌ی .tmp ها
grep -rl FLAG . | xargs cat | grep -c FLAG   # زنجیره‌ی واقعی کارآگاهی!

exit code: دستور موفق بود؟

grep FLAG file.txt
echo $?                        # 0 = موفق، غیرصفر = ناموفق/پیدا نشد

این عدد بعداً در اسکریپت‌نویسی همه‌جا به کار می‌آید.

تمرین (در آزمایشگاه خودتان انجام دهید)

  1. تعداد فایل‌های /usr/bin را بشمارید — بدون باز کردن هیچ فایلی.
  2. ۱۰ خط آخر /etc/passwd را در فایلی ذخیره کنید، بعد بدون بازنویسی، ۵ خط اول را هم به همان فایل اضافه کنید.
  3. دستوری بنویسید که خطای آن در /dev/null گم شود و فقط خروجی ببینید.
  4. خروجی history را هم روی صفحه ببینید هم در فایل ذخیره کنید.
  5. با یک زنجیره، تعداد کاربران واقعی (خط‌های دارای /home) در passwd را بشمارید.

پاسخ‌ها:

پاسخ ۱

ls /usr/bin | wc -l

پاسخ ۲

tail -10 /etc/passwd > f.txt && head -5 /etc/passwd >> f.txt

پاسخ ۳

ls /nope 2>/dev/null

پاسخ ۴

history | tee h.txt

پاسخ ۵

grep /home /etc/passwd | wc -l

⚙️ آموزش فرایندها و زمان‌بندی

هر برنامه‌ی در حال اجرا یک «فرایند» است — یاد بگیرید ببینیدشان، بکشیدشان و زمان‌بندی‌شان کنید.

فرایند چیست؟

هر برنامه‌ی در حال اجرا یک شماره یکتا دارد: PID. کرنل همه‌ی فرایندها را در /proc نگه می‌دارد — هر پوشه‌ی عددی، یک فرایند زنده است. فرایندها سلسله‌مراتب دارند: هر فرایندی «پدر» دارد.

دیدن فرایندها

ps aux                  # همه‌ی فرایندهای سیستم (a=all, u=جزئیات, x=بدون ترمینال)
ps aux | grep python    # فقط پایتون‌ها
top                     # نمایش زنده + مصرف رم/CPU (q = خروج)
cat /proc/1/cmdline     # PID یک همیشه اولین فرایندِ سیستم است

ستون‌های مهم ps: PID شماره، %MEM رم، COMMAND خود دستور. در آزمایشگاهِ شما PID 1 همان box-init است — یعنی «init» سیستم شماست؛ اینجا systemd نداریم.

کشتن فرایند

kill 1234               # درخواست مهربان (SIGTERM) — «لطفا ببند»
kill -9 1234            # زور (SIGKILL) — آخرین راه‌حل
killall sleep           # با نام بکش
pkill -f myscript.sh    # هر فرایندی که خط فرمانش این الگو را دارد

پس‌زمینه: & و nohup

python3 web.py &        # در پس‌زمینه اجرا شود (ترمینال آزاد بماند)
jobs                    # فرایندهای پس‌زمینه‌ی همین ترمینال
fg %1                   # برگرداندن به پیش‌زمینه
nohup python3 web.py &  # حتی با بستن ترمینال زنده بماند

نکته‌ی آزمایشگاه: با خوابیدن باکس، فرایندها می‌خوابند اما وقتی برگردید با mybox همه سر جایشان است. اما اگر باکس «بازنشانی» شود، از نو می‌شوند — برای کارهای دائمی از cron استفاده کنید.

cron: زمان‌بند لینوکس

cron سرویسی است که هر دقیقه بیدار می‌شود و چک می‌کند «کارِ این دقیقه چیست؟». در آزمایشگاه شما cron فعال است.

cat /etc/crontab        # جدول اصلی زمان‌بندی سیستم
ls /etc/cron.d/         # جدول‌های اضافی

ساختار هر خط: دقیقه ساعت روزِماه ماه روزِهفته کاربر دستور

# m  h  dom mon dow  user  command
*/2 *  *   *   *   root  /opt/lab/task.sh        # هر ۲ دقیقه
0 3  *   *   *   root  /opt/lab/night.sh         # هر روز ساعت ۰۳:۰۰
@reboot                     root  /opt/lab/start.sh     # موقع بالا آمدن
نکته: بعد از ویرایش cron نیازی به restart نیست — هر دقیقه دوباره می‌خواند. برای دیدن نتیجه‌ی */2 حداکثر ۲ دقیقه صبر کنید یا اسکریپت را دستی اجرا کنید.

systemd کجاست؟

روی سرورهای واقعی مدیر سرویس‌ها systemctl است (systemctl status nginx). اما کانتینر آزمایشگاه شما systemd ندارد — چون کانتینر «یک کارِ ساده» است نه یک ماشین کامل. هرجا سرویس خواستید، با cron/@reboot یا nohup خودتان بالا بیاورید.

تمرین (در آزمایشگاه خودتان انجام دهید)

  1. PID فرایندی را پیدا کنید که اسمش sleep است و بکشیدش.
  2. یک sleep 1000 در پس‌زمینه اجرا کنید، با jobs ببینید، بعد با kill بکشیدش.
  3. در /etc/crontab کاری اضافه کنید که هر دقیقه تاریخ را در /tmp/tick.txt اضافه کند؛ ۲ دقیقه بعد نتیجه را ببینید.
  4. همان کار را با @reboot هم ست کنید و باکس را از پنل ریست کنید تا ببینید کار می‌کند.
  5. چرا kill -9 را «آخرین راه» می‌دانند؟

پاسخ‌ها:

پاسخ ۱

ps aux | grep sleep → kill <PID>

پاسخ ۲

sleep 1000 & → jobs → kill %1

پاسخ ۳

* * * * * root date >> /tmp/tick.txt (به /etc/crontab اضافه کنید)

پاسخ ۴

@reboot root date >> /tmp/boot.txt

پاسخ ۵

چون به فرایند فرصتِ ذخیره/بستن فایل‌ها را نمی‌دهد و وسط کار قطعش می‌کند.

چالش‌های مرتبط

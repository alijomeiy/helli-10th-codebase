# راهنمای نصب و راه‌اندازی (فارسی)

> راهنمای گام‌به‌گام برای اجرای سیستم studentctl روی یک سرور لینوکس.
> این فایل توضیح می‌دهد هر بخش چه می‌کند و چگونه سرویس‌ها را بالا بیاورید.

---

## این سیستم چیست؟

یک محیط تمرین لینوکس برای حدود ۱۰۰ دانشجو روی یک سرور **۸ گیگابایت رم / ۴ هسته**:

- هر دانشجو یک حساب کاربری محدود می‌گیرد و می‌تواند یک سرویس ساده
  (مثلاً `python3 -m http.server`) روی یک پورت اختصاصی اجرا کند.
- یک **پنل وب فارسی/راست‌چین** (که در کانتینر Docker اجرا می‌شود) برای ثبت‌نام
  دانشجویان، تأیید توسط مدیر، و نمایش رمز SSH و ظرفیت لحظه‌ای.

### مدل دسترسی (ساده، مبتنی بر ظرفیت)

- **زمان‌بندی حذف شد.** هر دانشجو هر زمان که ظرفیت سرور آزاد باشد می‌تواند وارد شود.
- محدودیت تنها این است: تعداد ورودهای هم‌زمان نباید از `max_concurrent` (پیش‌فرض ۳۰)
  بیشتر شود.
- اگر دانشجویی **بیکار** بماند، پس از `idle_timeout` ثانیه (پیش‌فرض ۱۸۰۰ = ۳۰ دقیقه)
  نشست او به‌صورت خودکار بسته می‌شود تا جای او آزاد شود.
- هر دو مقدار از طریق پنل مدیریت قابل تغییرند.

## معماری در یک نگاه

```
  ┌─────────────────────────────────────────────┐
  │   سرور لینوکس (۸GB / 4Core) — یک ماشین       │
  │                                               │
  │  ┌──────────────┐     ┌────────────────────┐ │
  │  │ sshd + PAM   │     │ کانتینر پنل (Docker)│ │
  │  │ + cgroups    │◄────│  Flask + waitress   │ │
  │  │ + quota/ufw  │ SSH │  پورت ۵۰۰۰          │ │
  │  │ حساب‌های دانشجو│     │  دیتابیس + کلید SSH │ │
  │  └──────────────┘     └────────────────────┘ │
  └─────────────────────────────────────────────┘
```

**نکته مهم:** پنل در کانتینر اجرا می‌شود، اما محیط بازیگریِ دانشجویان
(sshd، PAM، cgroup، سهمیه‌ی دیسک، فایروال) روی خود میزبان می‌ماند؛ زیرا این
امکانات به هسته‌ی سیستم‌عامل نیاز دارند و درون کانتینر به‌درستی کار نمی‌کنند.

---

## پیش‌نیازها

- یک سرور با اوبونتو 22.04/24.04 یا دبیان 12، با رم ۸ گیگابایت و ۴ هسته.
- دسترسی root.
- Docker نصب‌شده (برای کانتینر پنل).
- (اختیاری) یک دامنه مانند `panel.yourdomain.ir` اگر می‌خواهید HTTPS داشته باشید.

---

## گام ۱: راه‌اندازی محیط بازیگری (سرور لینوکس)

این کار را **یک‌بار به‌عنوان root** روی سرور انجام دهید:

```bash
# اگر فایل‌ها را روی ویندوز کپی کرده‌اید، ابتدا پایان خطوط را درست کنید:
find server -name '*.sh' -exec sed -i 's/\r$//' {} +

cd server
sudo bash setup_server.sh
```

این اسکریپت چه می‌کند؟
- بسته‌های `jq`، `quota`، `ufw`، `openssh-server` را نصب می‌کند.
- **منطقه‌ی زمانی را روی `Asia/Tehran` تنظیم می‌کند.**
- اسکریپت‌های مدیریت `studentctl-*` را نصب و قلاب PAM را به `/etc/pam.d/sshd`
  اضافه می‌کند (کنترل ورود بر اساس ظرفیت).
- خروج خودکارِ بیکار را برای پوسته‌ی دانشجویان فعال می‌کند (پیش‌فرض ۳۰ دقیقه،
  از فایل پیکربندی خوانده می‌شود).
- محدودیت cgroup برای هر نشست: `MemoryMax=384M`، `CPUQuota=50%`، `TasksMax=128`.
- فایروال را برای SSH و بازه‌ی پورت دانشجویان (10000–10100) باز می‌کند.
- یک کاربر مدیریت `studentctl` می‌سازد با sudo بدون رمز **فقط** برای اسکریپت‌های مجاز.

### یک کار دستی (یک‌بار)

سهمیه‌ی دیسک را فعال کنید: در `/etc/fstab` گزینه‌ی `usrquota,grpquota` را به خط
مربوط به `/` اضافه کنید، سپس:

```bash
sudo mount -o remount / && sudo quotacheck -cum / && sudo quotaon -v /
```

(در صورت نیاز سرور را ری‌استارت کنید.)

## گام ۲: اجرای پنل (کانتینر Docker)

روی **همین سرور** (یا یک ماشین دیگر که به سرور دسترسی SSH دارد)، با فرض نصب‌بودن Docker:

```bash
bash deploy/deploy_panel.sh
```

این فرمان:
- اگر `panel/panel.env` وجود نداشت، آن را از روی نمونه می‌سازد و یک کلید مخفی
  تصادفی در آن می‌گذارد.
- تصویر کانتینر را می‌سازد و آن را اجرا می‌کند.
- در اولین اجرا، یک **کلید SSH** تولید و کلید عمومی را چاپ می‌کند.

### پیکربندی `panel.env`

پیش از ادامه، فایل `panel/panel.env` را ویرایش کنید:

```bash
nano panel/panel.env
```

مقادیر مهم:
- `STUDENTCTL_SSH_HOST` — نشانی سرور بازیگری. اگر پنل روی **همان سرور** اجرا می‌شود،
  مقدار را `host.docker.internal` بگذارید.
- `STUDENTCTL_SERVER_DOMAIN` — نشانی‌ای که دانشجویان برای SSH استفاده می‌کنند.
- `STUDENTCTL_ADMIN_PASS` — رمز اولیه‌ی مدیر؛ **حتماً تغییر دهید.**
- `STUDENTCTL_MAX_CONCURRENT` و `STUDENTCTL_IDLE_TIMEOUT` — سقف هم‌زمان و زمان خروج
  بیکار (بعداً از پنل هم قابل تغییرند).

پس از ویرایش، کانتینر را دوباره راه‌اندازی کنید:

```bash
docker compose up -d
```

### نصب کلید SSH روی سرور بازیگری

خروجیِ کلید عمومی (که هنگام اولین اجرا چاپ شد) را روی سرور بازیگری قرار دهید:

```bash
# روی سرور بازیگری:
sudo -u studentctl mkdir -p /home/studentctl/.ssh
echo '<کلید-عمومی-چاپ-شده>' | sudo -u studentctl tee -a /home/studentctl/.ssh/authorized_keys
```

## گام ۳: ورود و استفاده

### دانشجو
1. به نشانی پنل بروید (مثلاً `http://<server-ip>:5000/` یا `https://panel.yourdomain.ir/`).
2. روی **ثبت‌نام** بزنید و فرم را پر کنید.
3. پس از تأیید مدیر، در **ورود دانشجو** رمز SSH و پورت اختصاصی خود را ببینید.
4. وارد شوید:
   ```bash
   ssh <username>@<server-ip>
   # سپس سرویس خود را روی پورتتان اجرا کنید:
   python3 -m http.server <port>
   ```
5. در مرورگر باز کنید: `http://<server-ip>:<port>/`

### مدیر
1. به `/admin/login` بروید (این نشانی در رابط دانشجو **نمایش داده نمی‌شود**؛ فقط مدیر
   آن را می‌داند).
2. با نام کاربری و رمزی که در `panel.env` گذاشتید وارد شوید. **رمز را فوراً عوض کنید.**
3. درخواست‌ها را تأیید/رد کنید، حساب‌ها را فعال/غیرفعال/حذف کنید.
4. در بخش «تنظیمات دسترسی» مقادیر `max_concurrent` و `idle_timeout` را تنظیم کنید.

## (اختیاری) HTTPS با nginx

اگر می‌خواهید پنل روی `https://panel.yourdomain.ir/` در دسترس باشد، nginx را روی
همان سرور جلوی کانتینر قرار دهید:

```bash
sudo apt-get install -y nginx
# panel.yourdomain.ir را به 127.0.0.1:5000 پراکسی کنید (نمونه در server/nginx_panel.conf)
sudo cp server/nginx_panel.conf /etc/nginx/sites-available/panel.conf
sudo sed -i 's/PANEL_DOMAIN/panel.yourdomain.ir/g' /etc/nginx/sites-available/panel.conf
sudo ln -s /etc/nginx/sites-available/panel.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d panel.yourdomain.ir
```

## جایگزین: اجرای پنل بدون کانتینر (روی فلزِ لخت)

اگر ترجیح می‌دهید از Docker استفاده نکنید:

```bash
find panel -name '*.py' -exec sed -i 's/\r$//' {} +
bash deploy/install_panel.sh
```

این روش پنل را در `/opt/studentctl/panel` با یک venv و سرویس systemd نصب می‌کند.

## عیب‌یابی سریع

- **دانشجو نمی‌تواند وارد شود** → فایل `/etc/studentctl/config.json` را بررسی کنید؛
  دانشجو باید `enabled: true` داشته باشد و تعداد واردشدگان کمتر از `max_concurrent`
  باشد. دلیل رد، به کلاینت SSH چاپ می‌شود.
- **پنل می‌گوید «ارتباط با سرور برقرار نیست»** → مطمئن شوید کلید عمومی پنل در
  `/home/studentctl/.ssh/authorized_keys` روی سرور است. اگر پنل در کانتینر است و
  سرور همان میزبان است، `STUDENTCTL_SSH_HOST=host.docker.internal` بگذارید.
- **دانشجو خیلی زود خارج می‌شود / اصلاً خارج نمی‌شود** → مقدار `idle_timeout` را در
  پنل مدیریت تغییر دهید.
- **سهمیه‌ها اعمال نمی‌شود** → `usrquota` در `/etc/fstab` فعال نیست؛ گام دستی بالا را
  اجرا کنید.

برای جزئیات بیشترِ تغییرات، `CHANGELOG.fa.md` و `README.md` را ببینید.
